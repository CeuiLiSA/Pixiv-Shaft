# V3 设计哲学

> 清楚的内容层级，安静的主题色表面，少量有性格的形状，以及操作后恰到好处的回应。

本规范把现有 V3 与用户已确认的 **App 推荐计划** 视觉合并成可复用的设计方法。适用于后续 V3 页面、Web 设计原型和 Android 实现。版本：2026-09-09。

## 三分钟接手

### 记住这六条，就能画出同一种风格

1. **先确定页面在讲什么。** 标题、图形、任务和主操作指向同一个对象。例如推广页讲 Pixiv-Shaft App，就展示产品邀请与产品教程。不要用别的内容替代业务对象。
2. **大面积安静，小面积强调。** 底色轻微染色，卡片近中性，主按钮使用主题实色。状态色有明确含义；图标区和 Hero 才能适当活泼。
3. **用字号和留白组织阅读。** 页面标题 → 一句说明 → 主区 → 分区标题 → 卡片内容。标题明显大于正文，数字大于数字单位。装饰标签不是正文。
4. **圆角分工。** Hero 30、卡片 22、图标容器 17、按钮胶囊；少量异形用在图标或完成徽章。形状变化要能说明哪个元素重要。
5. **一个区域只有一个最强操作。** 主操作实色，次操作浅色，解释入口文字或描边。任务状态、条件、进度和按钮放在一起，让下一步一眼可见。
6. **轻轻回应，不持续表演。** 按下缩到 0.96、按钮圆角短暂变化、弹窗短距离入场。滚动时保持稳定，减少动态效果模式下取消装饰动画。

### 直接开始的步骤

1. 写一句业务目标：谁来到这里、要完成什么、完成后发生什么。
2. 从下面的页面配方选一个；先放标题、主内容和主操作。
3. 打开图鉴看日夜与三套主题，复制 starter 的结构和组件。
4. 填入真实状态与清楚的按钮文案；再添加一个视觉记忆点。
5. 对照验收清单检查手机、深色、长文案与完整流程。

**交给下一位设计师或 Agent 的简短指令：**

```text
按 docs/v3-design-philosophy.md 设计 [页面名称]。
业务对象是 [对象]；用户的主要目标是 [目标]；主操作是 [动作]。
采用 [运营 / 管理 / 设置 / 内容] 配方，参考 App 推荐计划的留白、字级与形状关系。
Web 复用 mockup/v3-design-system/tokens.css 和 components.css；从 starter.html 开始。
Android 复用 witstudio 与 V3Palette，尺寸用 dp/sp，关键操作热区至少 48dp。
保持中性染色底、22px 卡片、层级明确的文字、胶囊动作、克制的异形与短促反馈。
提交深浅主题、手机与宽屏、正常/空/加载/错误/完成状态和可操作的主要流程。
英文和数字使用 Montserrat 的真实字重，中文用系统中文字体回退；按规范选字号、字重、行高与语义文字色。
先校验业务语义，再检查视觉一致性；遇到信息不足要明确示例或待定值。
```

### 广场（2026-09-16 起按 V3 语言实现）

广场列表、帖子详情和创建帖子是 V3「作品 / 内容」配方的普通页面，**不再是 Figma 专项**。[Five Degrees 的 Post 区域](https://www.figma.com/design/XIelCCTiUHLjsJ9BbLmFy3/Five-Degrees?node-id=10025-6103) 只保留为内容区元素顺序与信息层级的参考；字体、图标、表面、圆角、动效与状态全部复用本文档和 `witstudio`：

- **字体**：Montserrat 400/500/600/700 承担英文与数字，中文走系统回退；广场不再携带 Inter 字体文件。
- **图标**：复用 app 现有图标（`ic_like_heart_*`、`ic_baseline_comment_24`、`chat_ic_emoji`、`ic_more_vert_black_24dp`、`ic_add_black_24dp`、`ic_close_black_24dp`、`ic_v3_chevron_24`），由 `V3Palette` 着色；不保留 Figma 导出的 `ic_plaza_figma_*`。
- **表面**：列表帖子**无界平铺**，与小说卡列表、评论列表同款：不套卡底、edge-to-edge，左右 16dp、上下 14dp 内边距，条目间只有通栏 hairline（`BottomDividerDecoration` + `hairline_divider`），点按用 `selectableItemBackground` 同款矩形涟漪；详情页帖子直接坐在 `v3_bg` 上（内容优先），评论同样无界平铺（与插画评论列表一致：无卡底、通栏 hairline、左右 16dp、上下 12dp），不做连通分段行；创建页字段放在 22dp 卡片内，引用入口是单个 20dp 分段行。图片格子 12dp 圆角、间距 4dp，单图 16dp。
- **回应**：32dp 视觉胶囊 + 48dp 触控热区；未选中 `alpha08` 底、次要文字色，选中 `alpha20` 底 + `alpha30` 描边 + `textAccent`；18sp 表情或同尺寸贴纸、14sp 等宽数字（`tnum`）。点赞心形按下一次 1.25 倍回弹，不循环。
- **顶栏与主操作**：三页 include `toolbar_layout.xml`；列表页顶栏中央放「全部 / 我的」MD3-E 连通分段（`bg_toolbar_segment_*`，同书签库），主操作是右下角实色胶囊 Extended FAB「发帖」，向下滚动收起、上滚出现；详情页保留标准「更多」菜单；创建页「发布」仍是标准菜单项。
- **状态**：首屏用 `FeedSkeletonView` 骨架（`PlazaSkeletonView`）而非文字；空 / 失败 / 不存在照 feeds 框架 `fragment_feed.xml` 的空态做：120dp 插画（空态 `empty_img`、错误 `ic_feed_error`）以 `textAccent` 60% 着色、一句 14sp 次要文字、至多一个主色胶囊动作，在列表区域居中；帖子详情评论为空时，同一套空态放在「评论 (0)」标签下方，最小高度 320dp，随列表滚动，不做成一行小字；分页加载与评论加载在列表底部显示进度，分页失败给「重试」胶囊。
- **底座**：广场帖子列表跑在 feeds 框架上（`PlazaFragment : FeedFragment`，数据源 `PlazaFeedSource`，变更与作用域在 `PlazaFeedController`）：分页、下拉刷新、冷启磁盘首屏、骨架容器、空 / 失败态、断网恢复重试、翻页节流与预算全部由框架负责，页面只保留顶栏分段、FAB、V3 状态样式、广场自己的错误文案与弹窗；刷新圈只在用户下拉时转，自动刷新与作用域切换静默加载。帖子详情暂未迁移。
- **动效**：广场所有列表 `itemAnimator = null`，条目更新直接就位，不做入场淡入、交叉淡化或位移（与下载管理列表同一取舍，作者明确不要列表动画）；只保留按钮与胶囊按下 0.96（胶囊 0.94）和点赞心形的一次回弹，系统关闭动画时跳过。

广场列表的评论预览使用 `V3Palette.alpha08` 叠加 `cardFill` 的主题派生底色，12dp 圆角；预览正文和回复入口以合成后的背景校正到至少 4.5:1 对比度，不使用白色或通用页面底色作为预览底。

广场举报使用独立 V3 页面，走「设置 / 表单」配方（2026-09-17 重做）：页面标题 →「请选择举报原因…」一句说明 → 举报对象卡 → 三个分区 → 贴底主操作。举报对象卡是 22dp 卡片加 17/17/17/7 图标容器，举报帖子/评论显示帖子与作者编号，举报作者只显示作者编号。分区标题是 20sp 粗体加末端的「必选 / 选填」小标，不把条件写进标题括号里。十类原因含「广告内容」，原因必选且不预选，做成连通分段行（20/5 圆角、2dp 行隙、56dp 行高）：控件仍是 `RadioButton` 保住读屏与分组语义，但系统圆点换成末端指示器——未选一圈描边，选中是实心主题色圆点加对勾，选中行同时换成主题浅底容器和强调文字。补充说明始终选填（包括其他原因），卡片底在外层容器上、输入框自身透明（两层圆角叠在一起会描出一圈深边），保持至少 168dp 高度与五行空间，字数计数在卡内右下。可选上传最多三张证据照片，做成三个等分方格，下一个空位本身就是虚线「添加」槽，不再挂一颗随照片数跳位的胶囊；每格右上是移除按钮，上传进度是格子底部的进度条。提交区贴底，上面压一条 hairline，失败说明用 danger 色留在按钮上方。提交成功后整页换成成功徽章（86dp 异形、绿色语义色、仅容器轻微倾斜）加标题与举报编号，而不是在原表单上改几个字。说明性正文和辅助文字一律用中性 `v3_text_2`，整页只有主操作、选中态和图标带主题色——长段落染成主题色会被读成链接。⚠️ `v3_text_3` 只有 33% alpha，压在 `cardFill` / `v3_surface_2` 上实测只有 **2.05:1**，不能拿来写「必选 / 选填」小标、字数计数、输入框提示这类承载信息的文字，它只配做纯装饰性的分区 eyebrow。页面内容可滚动、宽屏最多 720dp；提交中禁止重复操作，失败保留输入。原因行热区至少 48dp，放大字体允许换行。

屏蔽作者使用独立确认弹窗，内容是同一套图标容器加说明。顶栏的屏蔽名单打开完整管理页，基于 `FeedFragment + FeedSource + feedRenderer`，由 feeds 统一承担首屏骨架、下拉刷新、空态、失败重试与视图复用；列表之上常驻一张说明卡交代「屏蔽仅作用于广场」，空态因此只说「暂无屏蔽用户」。记录是一条横排卡片：首字母头像（接口没有头像字段，用主题浅底的首字承担识别位）→ 用户名与 UID → 末端的解除胶囊。胶囊有行宽上限（卡内宽度的 42%），放大字体下它自己换行，用户名列不会被挤成一列单字；解除按钮保持 48dp 热区，宽屏最多 720dp，列表不做条目动画。实现与验收见 [广场举报](plaza-moderation.md)。

所有帖子公开，不呈现可见范围设置；图片上限为 9 张，Linked Quest 对应 Pixiv 作品或用户引用。系统状态栏、键盘及字体放大使用 Android 原生能力。对照记录见 [广场设计验收](plaza-design-review.md)。

### 版本历史与更新弹窗（2026-09-17 起按 V3 语言实现）

`ceui.lisa.update` 整包按 V3 重做，是「下载 / 历史 / 管理」配方的样板：

- **版本历史**跑在 feeds 框架上（`FragmentVersionHistory : FeedFragment`，数据源 `VersionHistorySource`）。
  GitHub 的 releases 一次返回完整一页，`nextCursor` 恒为 null；首屏骨架（`VersionHistorySkeletonView`
  画的是卡片内容而不是实心板）、下拉刷新、空态、失败重试与断网恢复重试全部由框架承担，页面只留
  顶栏、720dp 限宽和卡片长相。列表 `itemAnimator = null`。
- 列表第一条是**紧凑汇总卡**：17/17/17/7 图标容器 + 「当前版本」+ 版本号（Montserrat 700、`tnum`），
  一条 hairline 之下是状态行，整页唯一的实色主操作「更新到 vX.Y.Z」就在它下面。已是最新时**不摆按钮**
  （没有下一步就不该有一颗按不动的胶囊，改成绿色对勾加一句话）；Google Play 渠道换成「请通过商店更新」。
- **发布卡**是 22dp 卡片：版本号 → 一枚状态小标（装着的那一版用主题浅底的「当前版本」，最新一版用中性
  `v3_surface_2` 的「最新」，一张卡只有一枚）→ 右端日期 → Markdown 更新说明 → 末端「安装包大小 + 展开胶囊」。
  说明默认折叠 6 行，展开入口是一颗 34dp 的次级胶囊加箭头——只画一行小字加箭头在满是 Markdown 的卡里
  读不出是个按钮。按钮显不显示在**卡片自己的 `onMeasure` 里**按 `TextView.getLineCount()` 定
  （绑定时先按文本长度猜一手，猜错才改一次可见性重量一遍）：`post` 到下一帧再显隐会让卡片在滚动中
  先矮一下再长高。⚠️ 正文**不能设 `ellipsize`**：设了之后 `Layout` 会被截到 `maxLines`、末行把剩下的
  文字并进来，`getLineCount` / `getLineEnd` / `getEllipsisCount` 就全都测不出「完整内容有多少行」
  （实测 6 行的卡不设 ellipsize 时 `lineCount` 是 14，设了就是 6，而省略号在多段 Spanned 上根本没画出来）。
- 更新说明里的**代码块**（如带 SHA 校验值的那几版）不用 Markwon 自带的 `codeBlockBackgroundColor`：
  那个只给得了一个颜色，画出来是贴着文字边的直角灰板，压在 22dp 卡片里很突兀。改成自绘的
  `LineBackgroundSpan`——12dp 圆角（首行末行各圆自己两个角）、左右 12dp 留白、上下各多画 6dp，
  底色是卡底再混一层 8% 主题色（同广场的评论预览）。行内代码不套底，只用等宽加 `textAccent`。
- **更新弹窗**是 V3 弹窗配方：顶角 28dp 的 sheet，图标容器 + 标题 + 「4.9.2 → 4.9.3」版本对比 →
  更新日志卡（高度有上限、自带渐隐边）→ 安装包名与大小 → 4dp 进度条 → 贴底的实色主操作
  （下载 / 下载中 / 安装 / 重试，各自带图标）→ 「稍后」「跳过此版本」两个纯文字入口。下载一旦开始，
  「跳过此版本」就收起。下载、校验与安装授权的逻辑没有改动。
- 两处的 Markdown 共用 `markwonFor(context)`：标题只比正文大一点，链接与行内代码走 `textAccent`，
  代码块坐在 `v3_surface_2` 上。

### 标签流（2026-09-23 起统一）

搜索发现、置顶/历史、作品详情与小说列表共用 `V3TagFlowView`，通用渲染下沉为
`witstudio.WitTagFlowView`；不再使用旧 `flowlayout-lib` 或在列表手写另一套标签。
胶囊底、描边、图标和原文从当前 `V3Palette` 派生，译文遵循「标签译文颜色」设置；
置顶与搜索历史正文只展示原文，已知官方译文仍可在长按菜单查看和复制。
原文与独立译文色都按当前主题的染色标签底校验对比度（至少 4.5:1），保留色相、校正亮度；
不能只用 HSL 亮度上限判断黄、绿等高感知亮度色是否可读。
英文使用真实 Montserrat Medium，中文系统回退；普通标签是 13sp、14dp 横向/6dp 纵向内边距、
按内容测量的约 32dp 可见胶囊，48dp 只作热区，落在上下各 8dp 的透明沿里（2026-09-24，#1148），
所以换行后可见胶囊之间约 16dp，不再额外叠加行距；紧凑小说卡
沿用原有密度。顶部搜索输入条内的标签保留 13sp 字号、14dp 横向/7dp 纵向内边距，
高度按内容测量，维持输入条原有尺寸。长标签允许换行，多行圆角封顶 24dp，避免底色变成椭圆；RTL 使用相对边距。
按压缩到 0.96，关闭系统动画时取消缩放。

搜索历史的删除是独立 48dp 按钮，不能把整颗标签的点击改成删除。删除键和正文坐在**同一颗**可见胶囊里：
自身不画第二层底，只有 16dp 的 `textTag` 色「×」和按下的圆形涟漪，48dp 热区落在透明上下沿与胶囊末端，
所以历史行与普通标签同为 32dp 可见高度（2026-09-24）。⚠️ 透明沿用 `InsetDrawable` 画时必须把它的
`getPadding` 置空：平台默认把 inset 报成 View 内边距，会覆盖条目自己的内边距，历史行因此被撑成 48dp 可见胶囊。
历史删除与搜索框标签的
「×」/ 长按删除均先打开 `WitDialog` 二次确认，正文写明目标；取消为普通操作，确认「删除」
使用 `WitDialogAction.ACTION_PROP_NEGATIVE`，确认前不改变数据或触发搜索。标签菜单统一提供
复制原文/已知译文、翻译、固定/取消固定、屏蔽/取消屏蔽；作者相关作品入口只由详情页提供。
ID、URL、作者搜索记录仍保留自己的路由与菜单，不按标签处理。组件能力与回归项见
[标签流迁移](tag-flow-migration.md)。

## 哪些是固定的，哪些可以变化

| 固定关系 | 可以随页面变化 |
| --- | --- |
| 底 → 容器 → 内容 → 强调的层级 | 页面是否有 Hero、统计栏、导航或大图 |
| 主题色与状态色分开 | 用户选择的主色、业务类型图标、有限的插图色 |
| 大标题、清楚正文、弱化辅助信息 | 文案、标题行数、内容密度与页面长度 |
| 胶囊操作与大小容器的圆角对比 | Hero 插图的对象、成功徽章的形状 |
| 一个区域的主次操作可辨 | 不同任务、阅读与管理场景的动作种类 |
| 稳定布局、及时反馈、完整状态 | 侧栏、单双栏与原生导航形态 |

**V3 是项目的整体语言，MD3-E 提供表达手段。** 本规范中的 Montserrat、22px 卡片、特定配色与角度是项目选择，不是 Google 强制尺寸。色彩、形状、大小、运动和容器应帮助用户识别重点，基本交互保持熟悉；这与 [Google 的 Expressive 设计说明](https://design.google/library/expressive-material-design-google-research) 一致。

原有作品/作者页的沉浸式背景、环境光和图片优先仍然适合内容页；本次确认的推介页补充了适合运营、会员与管理页面的安静表面、大字标题和异形装饰。不要为所有页面强加同一个运营 Banner。

## 文案：直接说明功能、条件与结果

页面文案采用克制、具体的产品语言。标题用于定位功能，说明交代条件，按钮标明动作，状态反馈报告结果。视觉上的表达由颜色、排版和形状承担。

- 页面名用「App 推荐计划」；任务用「发布 App 推荐帖」「邀请 3 位活跃好友」。避免把运营术语（如「拉新」「导流」）直接写给用户。
- 主视觉写「推荐 Pixiv-Shaft，领取 PRO 体验卡」，并在相邻说明中明确完成条件。奖励时长、期限与审核要求用准确数字。
- 成功反馈写「已提交」「已存入卡包」「已激活」，后接必要的预计时间或下一步。空态写「暂无体验卡」，再说明领取方式。
- 按钮用「领取体验卡」「查看卡包」「确认激活」。不写「收下回礼」「开始探索」「去看看」。
- 不使用「一起发光」「有了回响」「更多可能，现在开启」等口号、拟人或情感暗示。不要替用户宣称喜爱、感谢或受鼓舞。
- 英文标签只作分类与识别，如 `REFERRAL PROGRAM`、`EXPERIENCE PASS`、`7-DAY ACCESS`；不叠加英文情绪口号。
- 分享模板写产品用途、下载入口和必要的奖励说明，不捏造个人使用感受。真实体验由用户填写。
- 演示说明简洁可见：「当前为功能预览，任务与奖励均为示例，不影响账号权益。」接口、归因和服务端实现细节放在开发文档中。

### 使用规则

- 页面大部分是 `bg` 和中性 `surface`。主题色优先用于主按钮、选择状态与少量引导标记。一个普通卡片不要同时使用彩色底、粗描边和浓阴影。
- 同一个颜色对一起使用，例如 `tint` 必须配 `on-tint`；不能把白字直接放在浅紫、浅绿上。深色主题的主按钮通常用深字。
- 成功 = 绿色，异常 = 对应状态色，同时给出图标或文字。类别图标的颜色不表示任务已完成。
- 原型 Hero 的奶油/紫色卡券是装饰插图色，不是会员等级或所有页面的全局强调色。线上 App 的 Premium 金色仍保持原有品牌语义。
- 玻璃只用于覆盖层和沉浸式内容，不给每张普通任务卡加模糊；不支持 blur 时仍需足够不透明的底。
- 对正文与按钮文字优先要求至少 4.5:1；大字号按平台规则检查。颜色要按**合成后的实际背景**测量，不按原始 HEX 猜测。

## 字体与阅读节奏

小说阅读器的段间距以**当前正文渲染行高**为单位：1.0 等于一行，0.0 不额外留白；
翻页和滚动共用包含用户行距的固定正文行高，源文本中的空行至少占一正文行。
段间距统一四舍五入到整数像素后再排版和渲染，避免逐段累积误差。新默认值为 0.6 行；
已有阅读设置的用户按升级时的字体、字号和行距换算一次段间距（包括未调整段间距时的旧默认值），
在 0–2.5 行范围内保留原来的实际留白；只有空设置使用新默认值。

**Montserrat 是 V3 的英文、数字与品牌字体。** 中文搭配 Noto Sans SC 或系统中文字体（苹方 / 系统 sans-serif），保持中文笔画与 Montserrat 的几何感协调。Montserrat 没有中文字形，不要期望单设它就能改变中文。

Web 字体栈：`Montserrat, Noto Sans SC, PingFang SC, Microsoft YaHei, system sans-serif`。套件的 `fonts.css` 直接引用仓库已有 400/500/600/700/800 字重，因此离线不必回退英文；App 推介原型沿用 Google Fonts 加载机制并切换为 Montserrat。使用真实字重，`font-synthesis: none`，不要用描边或阴影假造粗体。

Android 复用 `app/src/main/res/font/montserrat_{regular,medium,semi_bold,bold,extra_bold}.ttf` 和 `textMontserrat*` 样式。中文由系统回退；复杂中文正文以可读性为主。只改变字体族不能形成层级，要同时指定以下字号、字重、颜色与行高。

| 角色 | 参考 Web | 建议 Android | 字重 / 行高 | 字体颜色与用法 |
| --- | --- | --- | --- | --- |
| 页面标题 | 32px，手机 28px | 28–32sp | 700 / 1.3–1.4 | `ink`，一个页面一级标题 |
| Hero 主标题 | 36–40px，手机 28–31px | 28–36sp | 800 / 1.4 | `ink`；少量关键词可用 `on-tint`，最多两三行 |
| 分区标题 | 20px，手机 19px | 20sp | 700 / 1.4 | `ink`，任务、权益、设置分组 |
| 卡片标题 | 15–16px，手机 15px | 16sp | 600 / 1.5 | `ink`，信息行起点 |
| 正文 | 套件 14–16px，原型 12–13px | 14–16sp | 400 / 1.7–1.9 | 关键说明 `ink`，次说明 `muted` |
| 控件标签 | 套件 12–14px | 14sp | 600 / 1.4 | 主按钮 `primary-ink`；次按钮 `on-tint` |
| 辅助说明 | 套件 11–12px | 12sp | 400–500 / 1.6 | `muted`，时间、来源、非关键标记 |
| 核心数字 | 40–55px | 40–48sp | 600 / 1.1 | `ink`，单位 12–14px / 400 / `muted` |

**原型仍有 7–10px 的英文装饰小字，这些仅属于插图与非关键标记。** 接入 Montserrat 时已把任务标题、正文和状态说明分别调整为 15–16、12–13、11px；可复用套件进一步以 14–16px 正文和 48px 热区作为起点，保留大小关系。金额、期限、条件、错误与操作不能缩到装饰字号。不要给整个中文标题套过大的负字距；Montserrat 的大数字可以略收紧（约 -1 至 -1.5px），进度与汇总用 `font-variant-numeric: tabular-nums`，避免更新时数字跳动。

Eyebrow（标题上方小标签）只用于少数主区，字距约 1.5–2px，内容简短；业务说明用中文正文。新增页面可以完全不使用英文。长标题换行，关键条件不省略，说明文字随系统字号增长。

## 布局配方：同一种语言，四种页面

| 页面 | 结构 | 表达重点 |
| --- | --- | --- |
| 运营 / 会员 / 引导 | 标题 → 一个 Hero → 分区 / 筛选 → 独立任务卡；宽屏加汇总侧栏 | 大标题、一处插图、明确回报与下一步 |
| 下载 / 历史 / 管理 | 标题 + 紧凑汇总 → 筛选 → 列表 → 条件出现的批量动作 | 内容密度、稳定行高、进度与操作；通常无 Hero |
| 设置 / 账户 | 标题 → 分组标题 → 连通分段行 → 必要说明 | 20/5 圆角关系、2dp 行隙、值与操作对齐 |
| 作品 / 作者 / 阅读 | 内容主视觉 → 关键信息 → 轻容器与操作 | 图片/文字本身优先；环境色、覆盖层适量使用 |

动图在作品页与大图页共用静图的双指缩放、放大后平移和双击缩放手势，操作期间继续播放。作品页单击动图打开大图，大图页单击切换工具栏；播放、重试与加载浮层固定在画布上方，不跟随画面缩放。适应尺寸时单指滑动交还列表，放大后优先平移画面，到边缘再交还父容器。

作品详情的普通竖向插画在实际图片栏宽度至少 600dp 时，高度不超过所在列表的可用视口，按比例完整显示，允许两侧留白。此规则适用于高宽比大于 1、低于 2.5 的 `illust`；漫画、超长图和窄栏继续按自然比例滚动展示。预览与原图使用同一尺寸规则，折叠、分屏或窗口高度变化后重新测量，不以物理屏幕宽度判断。

原型宽屏画布参考：100px rail、主内容最大 1360px（含水平内边距）、内容与侧栏 `minmax(0,1fr) 300px`。1180px 以下可压缩留白；760–980px 收成单主列，汇总与说明并排；760px 以下手机单列，rail 收起，需要时使用底部导航。

这些是 Web 演示断点，**不是 Android WindowSizeClass 阈值**。Android 根据可用窗口与现有导航体系决定单双栏。浮动导航要预留内容底部间距和系统安全区，键盘出现时表单动作仍可到达。

### 平板内容页

[平板设计方案与交互原型](tablet-design/README.md) 展示同一套 V3 在画廊和发现页中的用法。两页共享设计套件的颜色与 Montserrat，内容页保留图片优先，不复制运营票卡或奖励文案。

## 组件配方

### Hero

业务标签 → 两行主标题 → 一两句价值说明 → 一个主按钮 → 必要条件。文案区约占宽屏一半，装饰区独立且 `aria-hidden`。手机优先保留文案和操作，减少插图或放在文字之后；不要靠缩小正文容纳插图。

标题示例「推荐 Pixiv-Shaft，领取 PRO 体验卡」；按钮示例「邀请好友」。用户在首屏就知道推广什么、要做什么。

### 任务卡 / 操作卡

```text
[类别图标] 类别 · 状态                    [7 天 PRO]
           任务标题
           一两句具体说明
           完成条件           1/3         [主/次动作 →]
           ━━━━━────────────────
```

上层承载任务与回报，下层承载进度与下一步。图标 40–48；宽屏动作行对齐正文起点，窄屏可回到卡片左缘以保护进度和按钮。进度同时提供文字与数字，不用长度暗示未定义的百分比。

| 状态 | 呈现 | 动作 |
| --- | --- | --- |
| 未开始 | 中性状态、条件与奖励清楚 | 查看任务 / 开始 |
| 进行中 | 有意义的计数或进度 | 查看进度 / 继续 |
| 审核中 | 提交成功与反馈时间；不要伪造进度 | 查看审核 |
| 需补充 | 问题原因、恢复方式 | 补充并提交 |
| 可领取 / 可完成 | 成功色标记、完成计数、醒目动作 | 领取奖励 / 确认完成 |
| 已领取 / 已完成 | 稳定完成标签与结果位置 | 查看卡包 / 查看结果 |

### 按钮、选择器与图标

- 主按钮：`primary + primary-ink`，实色胶囊；次按钮：`tint + on-tint`；低优先级入口：文字/描边。控件图标保持约 20–22px、线宽约 1.7，采用统一 SVG 或原生图标系统。
- 通用套件操作热区至少 48px；Android 至少 48dp。原型里的 38–44px 视觉控件可以保留外观，但生产实现应扩大真实热区。
- 筛选器：浅底连通组、选中项独立浅色容器，计数为次级小标。单选用 `aria-pressed` 或完整 tab 语义；如果使用 tab，必须实现键盘切换和面板关联。
- 同层按钮保持相近高度，文字长就换布局；不要把整行操作压成难读的小字。图标按钮提供名称，装饰图标不重复朗读文字。
- 分类 Tab 对应多页内容时，点击与左右滑动共用同一分页状态；指示滑块连续跟随拖动进度，反向拖动和取消手势也同步回退。各页保留独立滚动位置，长标签或大字体下让选中项保持可见。表情选择器的 Tab 统一靠起始侧排列，BottomSheet 的关闭按钮位于同一行末端。

每日推荐入口位于发现页「其他分类」，紧随「人气画师」，沿用主题色分类按钮；点击进入带标题和返回按钮的独立页面。首页推荐区只保留「推荐作品 / 热门标签」两个 Tab，并保留用户配置的顺序；两个 Tab 等分整行宽度（`fixed + fill`），标题在各自半区居中，保留至少 48dp 触控高度，不按内容宽度聚在整行中央。Lite 渠道不显示每日推荐入口（2026-09-18）。

官网发现（2026-09-19）在发现页「其他分类」增加独立入口，与原「发现」候选池并列。内容页使用标准工具栏、浅底分级选择条与现有作品瀑布流；全部 / 全年龄 / R-18 支持点击及左右滑动，各页独立保留列表和滚动位置。默认分级跟随当前 R-18 过滤设置；长标签与大字体时选择条可横向滚动，触控高度至少 48dp。缺少网页会话或网页账号与 App 不一致时，空态提示使用同一账号并提供「去登录」，工具栏菜单保留网页登录以便会话过期后重登。骨架、失败重试与分页状态沿用 feeds 框架。Lite 渠道与 Web 首页一样隐藏此入口。

### 本地库筛选面板（2026-09-25）

### 发现页底部交流入口（2026-09-18）

`FragmentCenter` 在榜单之后展示「交流与分享」，由原生 [DiscoverSocialSection](../app/src/main/java/ceui/pixiv/ui/discovery/DiscoverSocialSection.kt) 和 [DiscoverSocialArtView](../app/src/main/java/ceui/pixiv/ui/discovery/DiscoverSocialArtView.kt) 实现。聊天室使用叠放气泡，社区使用错落帖卡与心形贴片；装饰为静态 Canvas 图形，文字使用原生 TextView、Montserrat 与系统中文回退。两张卡各为一个可聚焦的按钮，箭头属于同一热区。只保留 `pressScale` 短促按压与涟漪，尊重系统动画设置。

所有强调色直接读取 `V3Palette.from(context)`：社区底为 `cardFill`，聊天室底为 `alpha20` 合成 `cardFill`，细描边为 `cardHairline`，插图使用 `primary` 与透明度色阶；文字从 `textAccent`、`onPrimary` 和日夜 `v3_text_*` 出发，按最终合成背景校正到至少 4.5:1。没有页面专属的固定紫色或另一套主色表。普通卡片没有阴影，轻微投影仅限插图。

模块随发现页滚动，沿用 `BottomSafeInsets`。可用宽度不足或字体放大时改为单列；正常字体下单卡使用左文右图，大字体下插图与文字上下排列，标题与按钮允许换行。聊天室和社区分别跳转 `TemplateRoute.CHAT` / `PLAZA`，在支持的渠道默认展示；侧边栏的两个旧入口、设置页的两个入口开关及对应存储字段均已移除。公开聊天室横幅仍由独立的通知开关控制，私信通知不受影响。社区是该入口的显示名，目标页仍为广场。标题、说明与操作文案覆盖简中、繁中、英、日、韩、俄、土七种语言。不增加在线人数、未读数或假动态。

### 汇总面板与卡包

主数字 40–55，单位 11–14，标签放在数字旁或下方。只展示有业务价值的 1–3 个汇总项，来源和单位清楚。可用小星形填补留白，但它不能看起来像可点击设置。

卡包显示来源、权益长度、有效期、状态与一个动作。领取和激活语义分开；完成反馈说明结果存放在哪里。不要让无关页面继承 PRO 奖励、有效期等示例业务。

App 推介计划的任务与卡包始终在同一页展示（2026-09-18）：手机在 Hero 下先展示奖励概览和卡包，再展示推荐任务；宽屏任务居左，奖励概览和卡包居右。卡片直接显示激活操作，空卡包显示领取条件；任务筛选仅影响任务列表。禁止用「查看卡包」替换任务列表、再重复整页顶部内容；领取反馈里的「查看卡包」和任务的「查看奖励」只滚动定位本页卡包。激活确认仍使用 Sheet。

### 弹窗、表单与反馈

手机 Sheet 贴底、顶角 28；桌面约 480px 居中。顺序：标题 → 当前状态 → 条件/字段 → 主操作 → 可选次操作。超长内容内部滚动；支持返回/Escape、焦点留在弹窗、关闭后回到触发元素。

作品详情的「页面预览」在标题右侧放「用阅读器看」紧凑次级胶囊（2026-09-23，#1145），复用 `witstudio` 的主题浅底，采用 13sp / 500 标签、16dp 书本图标、左右 12dp 留白；可见胶囊约 32dp 高，透明上下沿保留 48dp 热区，避免按钮抢过标题。窄屏、长译文或字体放大导致同排放不下时，操作换到下一行，文字可换行。V2 / V3 共用此入口；单图不显示 `1 / 1`，阅读器入口放在「更多」菜单。离线快照只预览本地页面，阅读器内部的预览不重复显示阅读器入口。

作品详情与二级大图页底部的「下载 + 收藏」悬浮胶囊默认居中，可在设置里改为靠左 / 靠右（2026-09-24，#1090）。靠边时胶囊离屏幕边 20dp（与二级大图页那一行的左右留白对齐），横屏侧边导航栏或挖孔在同侧时再叠加其 inset，收藏心固定在贴屏幕边的外侧，其余段镜像排开，评论跳转段落在靠屏幕内侧的一端；「下载 / 收藏顺序」只在居中时生效，设置里也只在居中时露出。二级大图页胶囊靠右时，同一行的页码让到左侧。两页共用 `V3FabBarController.applyLayoutPreference`，底距规则不变。

小说阅读器的搜索结果行保留「序号 → 两行摘录 → 右下角全文位置」的层级（2026-09-23，#1138）。位置按命中起点占原文字符总数的比例向下取整，显示整数百分比，不随字号、分页或滚动模式变化；使用 12sp Montserrat Regular 与日夜 `v3_text_2` 灰色。百分比独占末端宽度，序号随位数和字体放大增宽，摘录占剩余空间；整行点击仍跳到该命中位置。

Android 的 `WitDialog` 菜单行以 52dp 为最小高度，长文案或字体放大时随文字增高，超高菜单由内容区滚动承接；不要固定行高裁切文字。字号与换行验收使用原生字体测量，覆盖 320dp 窄屏和 2 倍字体（2026-09-20，#1102）。

小说朗读设置使用同一套可滚动 `WitDialog` 和连通分段行，集中显示速度、高亮、自动跟随、双击跳转与常驻入口开关。高亮使用阅读器自身主题的高亮色；“从本页开始朗读”是至少 48dp 的次级胶囊，避让底部系统安全区，工具栏展开时收起并在菜单保留入口。只有朗读位置不在当前页面时显示常驻入口。自动跟随只移动当前小说的页面或滚动位置，双击从命中的段落开头重读（2026-09-23，#1139）。

小说阅读器的「文字颜色」位于配色下方，分别为每种阅读配色记住正文与章节标题的字色，支持恢复当前配色的默认字色（2026-09-23，#1142）。复用现有 HSV / HEX 取色器，在阅读背景上预览候选字色；确认后同时应用到翻页与滚动阅读，取消不保存。取色器标题与操作分行，预览及输入区随字体增高，窄屏、长译文和放大字体时由内容区滚动承接。

表单使用常驻标签、浅底圆角输入框、字段附近的错误原因。提交中避免重复操作，服务端完成后再呈现成功。网络失败保留已填内容并给出重试。

短暂 Toast 适合“已复制”等非阻断反馈；影响操作的错误保留在页面或字段旁。成功可用一次异形徽章，但应同时说明结果。空状态描述原因并提供一个真实可用动作；加载、空、错误不能都呈现为空列表。

破坏性操作使用语义危险色：广场菜单的「删除帖子」，以及「放弃草稿」「删除帖子」弹窗中的执行按钮采用 destructive 样式；Android 确认按钮复用 `WitDialogAction.ACTION_PROP_NEGATIVE`。「取消」「继续编辑」和弹窗正文保留普通样式，危险色跟随日夜资源，不随用户主色变化。

## 动效

| 场景 | Web 建议 | 约束 |
| --- | --- | --- |
| 颜色与选中状态 | 160–200ms，标准缓动 | 不改变布局大小 |
| 按压 | 0.96 scale，约 300ms 弹性近似 | 不让按钮逃离手指 |
| 卡片入场 | 350ms，位移约 7px | 首次出现一次；最多少量错峰 35ms |
| Sheet | 300ms，位移约 20px | 背景遮罩同步，无长距离飞入 |
| 进度变化 | 约 500ms | 仅在真实数值变化后更新 |
| 成功 | 轻微形状/尺度反馈一次 | 不循环抖动、不强制烟花 |

参考曲线 `cubic-bezier(.2,.85,.25,1.25)` 是 CSS 的弹性**近似**；Android 采用宿主支持的 spring/motion 实现，不能把曲线参数当物理弹簧参数照填。减少动态效果时关闭非必要位移/缩放，保留清楚状态。原生同时尊重系统动画设置。

Web 参考值和 Android 当前基础色**不完全相同**，这里统一的是视觉关系。新规范不会自动重写全 App 颜色，也不要求把 Web 原型嵌入 WebView。新增全局角色应同时补日夜资源并检查既有使用处；页面局部表达从主题派生。

普通内容页需要与设置页对齐的顶栏时，复用 `fragment_settings_hub.xml` 的 Toolbar：`wrap_content`、`fitsSystemWindows=true`、宿主 `colorPrimary`、居中 18sp 标题和同款返回图标，并调用 `BaseFragment.applyToolbarInsets(activity, root)`。Material3 完整主题仅放在顶栏下方的内容容器，避免覆盖用户主色；不要用固定 Toolbar 高度再叠加状态栏 padding。真机对照设置页核验标题位置、顶栏高度和主题色。

独立内容页优先直接 include `toolbar_layout.xml`；顶栏消费 Insets 时，API 29 及以下通过现有 `ViewGroupCompat.installCompatInsetsDispatch` 保证内容区继续收到 Insets。页面跳转沿用统一宿主和系统预测性返回；只在草稿未保存、正在提交或面板需要收起时启用返回拦截，并随状态变化立即更新 enabled，禁止常开回调再在回调内部判断是否退出。`TemplateActivity` 显式开启 `enableOnBackInvokedCallback`，兼容 Android 13–15 的选择性启用机制。

至少验证预设主色中的紫/粉/青绿/亮黄和一个自定义 HEX。背景跟随主题不代表文字已经可读；尤其亮黄不能仅用固定 HSL 亮度猜测。字号用 sp，布局用 dp，支持字体缩放与 TalkBack。

[Android 官方无障碍建议](https://developer.android.com/guide/topics/ui/accessibility/apps) 提供文字对比度与触控尺寸依据。本规范将关键操作热区设为至少 48dp；旧原型的装饰小字与局部 44px 控件不是豁免。

## 从空白到成稿：一个可复制的例子

以“本地下载管理”新页面为例：

1. 目标：用户看清下载状态并继续未完成任务；主操作「继续全部」。
2. 选管理配方：省去运营 Hero，用标题「下载管理」与紧凑汇总。
3. 筛选：全部 / 下载中 / 已完成；计数按真实列表计算。
4. 下载项：封面或类型图标 → 文件名与来源 → 已下载/总大小 → 进度 → 暂停/继续。失败项显示原因和重试。
5. 保留 V3 的中性染色底、22px 卡片、主题操作、清楚字级；需要批量选择时再出现浮动动作栏。
6. 用深色、亮黄主题、320px 窄屏、长文件名和大字级验证。

即使没有票卡、星形、PRO 或邀请任务，也应与推介页面看起来属于同一产品。这就是可迁移的设计语言。

## 维护方式

这份文档是 **设计决策入口**；新 Web 原型的变量在 `mockup/v3-design-system/tokens.css`、基础组件在 `components.css`；Android 的运行时资源继续以 `witstudio` 为准。App 推介原型保留已确认的布局与自身样式；本次按用户要求同步采用 Montserrat 并完善字号层级，未重构为新组件库。

调整通用风格时同步更新规范、套件与图鉴；改变已确认页面的视觉另行按任务范围处理。只属于一页的业务，不上升为全局规范。新增规则要有一个可看的例子和明确适用范围，避免积累抽象形容词。

贴纸选择器的分段分类以小说阅读器设置为准：复用 reader segment 轨道与选中背景，42dp 视觉高度、48dp 触控高度，整体按文案收紧；选中底使用宿主主色。贴纸选择器不显示标题，左侧主题色文字关闭与右上角分类同排。滚动内容延伸到导航栏区域，由滚动容器自身的 bottom padding 保留到底后的安全距离，clipToPadding=false；不要给整张 sheet 垫出固定底部空白条。

聊天贴纸按独立图片展示：64dp 图像、无气泡背景与阴影，尺寸大于选择器的约 32dp 缩略图；引用内容使用独立主题浅色块，不能把依赖彩色气泡的白字直接放到页面底色上。
