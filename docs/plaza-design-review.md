## 第二轮修正

- 使用指定行高，避免 Android 字体 metrics 再乘倍数造成正文和标题额外增高。
- 九宫格恢复设计宽高比；表情胶囊宽度、emoji 字号与换行间距对齐设计。
- 缩小评论预览的额外留白，区分作者与内容的文字角色。
- 详情底部补充真实回应数、评论数；评论按钮定位评论或进入回复。
- 评论正文与头像并排，子回复缩进；列表复用时还原正文左边距。
- 创建页设置 inputType 后重新应用 Inter，避免系统重置字体；恢复小尺寸引用入口，隐藏空错误占位。
- 移除可见范围 UI 及其专用图标。所有帖子公开，最多 9 张图，引用为 Pixiv objectId/objectType。

## 数据与设计边界

动态内容来自真实帖子，不硬编码设计中的姓名、时间、计数或照片。Figma 示例的 Quest 映射为 Pixiv 作品/用户引用；视频、可见范围和示例置顶标签不属于本次帖子需求。详情底部回复已改为页内输入与发送，使用聊天室共享布局、引用条和键盘/贴纸面板切换，不再打开独立创建回复页。文字发送失败保留草稿，成功清空并刷新评论；贴纸仍作为帖子回应。创建帖子继续使用原有图片上传与草稿流程。

## 帖子大图（2026-09-15）

帖子图片复用插画二级详情的 `ImageDetailActivity`、`FragmentImageDetail` 和 `SketchZoomImageView`。点击时传入真实缩略图的屏幕矩形，复用展开、竖向拖拽、回弹、缩回和预测式返回动画；不另建 Dialog 或手写缩放控件。翻到其他图片后退出，沿用现有查看器的淡出行为。

广场只提供图片数据源：保留媒体 ID 缓存，签名有效时不请求帖子接口，过期时合并刷新；最多九张图片保持原始顺序，重建后保留当前页。页码使用国际化资源，插画专属的收藏和 AI 操作不用于帖子媒体。

## 详情页内回复（2026-09-16）

按用户确认，底部改为复用聊天室的 `chat_view_composer.xml` 与主题样式。键盘、贴纸面板和导航栏安全区交给 `BottomPanelCoordinator`，详情 Header 不再重复叠加底部 Insets。评论回复在底部显示引用条；发送失败保留草稿和请求 ID，成功清空并刷新，下一次回复使用新的请求 ID。

## 回应尺寸（2026-09-16）

重新通过 Figma Desktop `get_design_context` 对照 `10131:8487` 和列表 `10063:6767` 的 `10063:6901` Reaction Stack：高 28px，表情 18px、计数 Inter Regular 15px，水平内边距 8px，表情与计数及胶囊间距均为 4px。列表完整节点读取超时后，读取其结构并缩小到 Reaction Stack 获取代码与截图。

原贴纸分支单独设置 48dp 最小高度、32dp 图片和带描边底板，导致列表、帖子和评论中的贴纸回应明显偏大。现改为复用已有回应胶囊，仅将其中的表情替换为真实贴纸资源；64px 解码档位不变，显示尺寸随 18sp 表情缩放，计数和选中态统一。

此次验证：GitHub Debug 编译、8 项现有布局测试通过；Pixel 8 实际帖子与评论的回应已与相邻操作同高，现有日夜渲染及输入交互检查通过。未提交任何评论或回应。

## 帖子共享缓存（2026-09-16）

列表、分页、详情与发布成功的完整帖子写入现有 `ObjectPool`，使用独立的 `PLAZA_POST` 类型和 `PlazaPostCacheEntry`（API 的 `objectType` 已用于 Pixiv 引用类型，故通过条目适配 `ModelObject`）。列表和详情观察同一对象，点赞、回应、删除同步更新；观察者随 ViewModel 清理，继续使用 ObjectPool 的有界 LRU。

详情进入时同步呈现同账号缓存。四分钟内、修订号一致且图片签名仍有效的帖子不重复请求详情接口；评论单独加载，慢响应或失败不会挡住已有正文。缓存过期和手动下拉时刷新完整帖子，冷启动也在取得帖子后立即显示，不再等待评论。跨账号缓存不复用，过期请求不能覆盖其他页面刚完成的修改；404 和删除清除共享帖子。

广场「全部 / 我的」首屏复用现有 `FeedFirstPageCache<PlazaPage>`、`feed_cache_table` 和 `feedCacheWriteScope`，按账号与列表范围隔离，不另建表或内存列表缓存。冷启动先恢复首屏，再网络刷新；读取本地期间不闪 loading，网络失败保留已有内容。只保存成功的网络首屏（含空首屏以清掉旧内容），分页不会替换首屏快照。

磁盘帖子只补入 ObjectPool 的缺失条目，保留旧时间并标记待校验，不覆盖已有新状态或删除标记；点击旧快照依然立即呈现正文，再后台校验。网络缓存命中则直接复用帖子，只单独加载评论。

上线前审查补充：缓存读取或结构恢复失败按未命中继续联网；首屏写盘使用现有进程级作用域并顺序写入，页面关闭不会取消写入，旧快照不会晚到覆盖新快照；跨 ViewModel 的操作响应按顺序更新 ObjectPool，避免点赞与回应的完整响应互相覆盖。账号在请求和落盘时固定，取消传播，观察者在 ViewModel 清理时释放。

此次验证：48 项广场单测、8 项 PixivFeedSource 缓存接线测试和 8 项通用首屏缓存测试通过；Pixel 8 的真实 Room 首屏恢复与断网保留、回复输入交互、图片刷新及退出 3 项测试通过。完整 lint 仍有既存 189 项 MissingTranslation 错误，本次缓存接入无新增 lint 错误。

下拉刷新动画只由用户实际下拉手势触发；自动恢复首屏、校验过期帖子、加载评论与发布后更新均不启动刷新圈。加载结束统一收起用户已触发的刷新圈，避免从列表进入缓存详情时短暂闪圈（2026-09-16）。

## 本批功能上线审查（2026-09-16）

范围为本会话的页内回复、回应尺寸、帖子共享缓存与本地首屏、聊天气泡内时间，以及自动加载不显示下拉刷新圈。检查了共享缓存调用方、账号隔离、请求取消与乱序、页面销毁、观察者释放、磁盘线程、分页与聊天布局复用。

第一轮修复两个状态问题：缓存帖子在评论加载期间的点赞、回应和删除曾被 loading 守卫直接丢弃；现允许操作，并用修订号拒绝旧响应，删除当前帖子同时取消待返回评论。详情 404 失效曾不推进修订号，旧列表响应可将删除帖子重新灌入对象池；现先推进修订号再写入删除标记。自动重试复用新鲜帖子，手动下拉保留强制刷新语义。

第二轮补充验证嵌套坏快照：Gson 可将 Kotlin 非空字段解析为 null，原本仅捕获整页映射异常不足以阻止坏帖子进入 UI。现先检查整页帖子及图片、回应、评论预览的必填字段，再恢复 ObjectPool；任何坏条目都使快照按未命中处理，不留下部分缓存。新增回归测试覆盖十种缺字段或空嵌套对象，并确认网络回退正常。聊天时间布局另将失败图标改用 `app:tint`，消除新增 Lint 错误。

最终验证：GitHub Debug 应用和测试 APK 编译通过；82 项 app 相关单测、8 项 feeds 缓存单测、2 项 panel 单测通过。Pixel 8 的首屏缓存、回复输入与重建、图片刷新退出、日夜帖子渲染、聊天时间布局共 5 项测试通过；聊天时间包含日夜、320/390/720dp、1/2 倍字号、收发消息等 216 种组合。完整 Lint 仍被既存 189 项 `MissingTranslation` 错误阻断，修正后本次改动无新增 Lint 错误。未进行长时间压力测试或性能剖析，不据此承诺所有设备与负载下绝无问题；审查范围内未发现剩余阻断性逻辑、崩溃或明显性能问题。

## 按 V3 语言重做三页（2026-09-16）

按作者要求，用 [V3 设计哲学](v3-design-philosophy.md) 与 MD3-E 重新审视广场，结论是此前实现"自成一派"：独立的 Inter 字体、Figma 导出且写死颜色的图标、6dp/4dp 小圆角、仅 28dp 高的回应热区、无按压反馈、加载/空/失败全部退化为一行状态文字，「全部 / 我的」筛选在 ViewModel 里有实现但没有任何入口。本轮把三页改回项目语言，Figma 只保留内容区元素顺序作参考：

- 字体统一为 Montserrat（数字与英文）+ 系统中文回退，删除 4 个 `plaza_inter_*.ttf`（约 1.3 MB）。
- 图标改用 app 现有资源并由 `V3Palette` 着色，删除 9 个 `ic_plaza_figma_*`。
- 列表与详情评论都是**无界平铺**（作者两次明确要求）：无卡底、通栏 hairline（`BottomDividerDecoration`），与小说卡列表、插画评论列表同款；创建页字段进入 22dp 卡片，引用入口为单个 20dp 分段行。
- 回应胶囊 32dp 视觉 + 48dp 热区，按下 0.94 缩放，点赞心形一次回弹；卡片、行与按钮使用主题涟漪。
- 顶栏中央「全部 / 我的」MD3-E 连通分段（复用书签库的 `bg_toolbar_segment_*`），列表右下角实色 Extended FAB「发帖」滚动收起。
- 首屏骨架 `PlazaSkeletonView`（共用 `FeedSkeletonView` shimmer）；空 / 失败 / 不存在为一张带动作的状态卡；分页与评论加载在列表底部显示进度，分页失败给「重试」胶囊。
- 所有广场列表 `itemAnimator = null`，不做入场或变更动画（作者反馈列表动画难看）。
- 新增 11 条文案，7 个语言目录同步。

验证：GitHub Debug 编译通过；广场 55 项单测通过（Robolectric API 28/35，含布局、状态、本地化、图片刷新）。Pixel 8 真机在紫色主题下逐页截图检查了列表（全部 / 我的）、帖子详情（含两条平铺评论与选中态回应）、创建页，以及深色模式的列表与详情；未发布、删除或回应帖子。未跑完整 lint。

## 空态对齐 feeds 框架（2026-09-16）

作者要求帖子详情没有评论时要有一块合适大小的空态区域，并且列表空态也要有，做法参考 feeds 框架。此前列表空态是一张自造的虚线状态卡，详情页评论为空时只剩「评论 (0)」标签下方一片空白。

现在两处共用 `PlazaStateView`，逐项照抄 `feeds/fragment_feed.xml` 的 `feed_state_container`：120dp 插画（空态 `R.mipmap.empty_img`、错误态 feeds 的 `ic_feed_error`）以 `V3Palette.textAccent` 60% alpha 着色、14sp 次要色文案（内边距 16dp）、至多一个主色胶囊动作。列表空态 / 失败 / 不存在在内容区居中；详情页评论加载完成且为空时，`PostAdapter.emptyComments` 让父帖子把同一空态放在「评论 (0)」下方，最小高度 320dp，属于列表内容，随页面滚动，评论到来后自动收起。评论仍在加载、分页或失败时不显示空态，避免闪现。

验证：GitHub Debug 编译通过，广场单测通过；Pixel 8 打开一条无评论帖子，滚到底部可见插画与「还没有评论,做第一个」占据合适区域。列表空态当前账号有帖子，未在真机触发。

## 列表页迁到 feeds 框架（2026-09-16）

第一步只迁帖子列表；详情页仍跑 `PlazaTimelineViewModel`（列表分支已从它的 Fragment 里拆掉，`PlazaTimelineFragment` 现在只服务详情）。目标是换底座不换表现：

- `PlazaFragment : FeedFragment(R.layout.fragment_plaza_feed)`，布局 = `toolbar_layout` + `feed_root`，`plaza_content` / `plaza_column` 沿用 720dp 宽屏收窄和底部 Insets。
- `PlazaFeedSource : FeedSource<Long>`：`loadFromCache` 读本账号本作用域的 Room 首屏快照并经 `restorePage` 校验（坏快照 / 读取途中账号变化 = 未命中）；`load` 在请求前后钉账号，响应期间修订号推进则重新拉取，成功帖子写入 ObjectPool，网络首屏（含空页）落盘、追加页不落盘。
- `PlazaFeedController`（ViewModel）：`mine` 存 SavedState；`enter()` 复刻原 resume 策略（首次 NONE、修订号变化或超过 4 分钟 REFRESH、账号变化 SWITCH_SCOPE）；点赞 / 回应 / 删除单飞，`busyIds` 映射为条目的 `busy` 字段，变更期间的刷新请求推迟到变更结束再回放；错误走 `plazaError` 和一次性弹窗；`ensureFreshImages` 原样搬入。
- 页面层保留：顶栏「全部 / 我的」分段、Extended FAB、通栏 hairline、`itemAnimator = null`、`PlazaSkeletonView`、V3 字体与主色胶囊的空态、`showPlazaError` 弹窗。刷新圈只在用户下拉时转（`onListCommitted` 里按 `userPulled` 收圈）；切换作用域或账号时清空列表、立即重刷并先显示该作用域的磁盘快照，切换期间用骨架占位；全屏错误文案用广场自己的状态码映射，分页失败同样弹一次窗。ObjectPool 观察者绑在 viewLifecycleOwner 上，随列表内容增减。
