# App 推介计划 · V3 / MD3-E 交互原型

打开 [index.html](index.html)，或在项目根目录执行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory mockup/referral-plan
```

访问 http://127.0.0.1:8765。页面为独立 HTML/CSS/JS，无构建步骤；英文与数字使用 Montserrat，中文使用 Noto Sans SC / 系统中文字体；Google Fonts 不可用时使用系统字体。数据仅存本浏览器，未接入 Android、后台、真实邀请或 PRO 权益。当前 App 推介版使用独立的 v2 演示存储，不会把旧任务的完成记录算作 App 推广奖励。

## 可以评审的交互

- 手机、平板、桌面自适应；顶部切换日夜模式，页尾切换紫色 / 玫瑰 / 青绿主题。
- 全部 / 进行中 / 可领取任务筛选；任务详情、完成标准、App 推荐帖 / 教程链接提交、审核反馈、补充重提。
- 领取 7 天 / 30 天卡片 → 卡包 → 确认激活 → 顺延权益；领取不开始计时。
- 邀请文案复制、邀请汇总进度、App 推荐素材与推荐帖提纲复制、活动规则。
- 页尾「演示控制台」模拟好友达标、审核通过 / 需补充和重置。初始数据含 1 位有效邀请、0 位持续活跃好友、1 项可领取奖励。

建议演示：领取首位邀请奖励 → 卡包激活 → 提交 App 上手教程 → 控制台审核通过 → 领取并激活 30 天卡，观察权益顺延。然后模拟增加 2 位有效邀请与 3 位持续活跃好友，体验进阶月卡。

## 设计映射

统一规范见 [V3 设计哲学](../../docs/v3-design-philosophy.md)，组件与新页面模板见 [V3 设计套件](../v3-design-system/README.md)。本页是已确认视觉基准；后续已按要求加入 Montserrat，并提高任务标题、正文和状态文字的阅读层级。

延续仓库 `mockup/user_detail_v3.html` 的主题染色、通透表面、胶囊控件和轻盈动效，以及 `V3Palette.kt` 的日夜双模与衍生配色思想。大面积中性表面保持内容清楚；主题色承担主操作和选择状态，绿色承担完成状态。

MD3-E 用在清楚的字级对比、错位体验卡、异形徽章、不同任务形状、按钮按压形变和强调动效上。Web 原型使用 CSS 曲线近似弹性反馈；Android 落地时应使用真实 spring/motion scheme、宿主主题 palette 和原生组件，而不是嵌入 WebView。所有交互支持键盘，弹窗使用原生 dialog 焦点约束，支持减少动态效果；手机主要操作保持 44px 以上。

## 建议的运营策略

推广对象是 **Pixiv-Shaft App 本身**。每项任务都围绕产品介绍、下载安装、实际使用或用户留存；推广链接最终指向官方 App 下载页或专属邀请落地页。

以下为待验证方案，不是已上线承诺，也没有虚构转化率。

| 任务 | 邀请人奖励 | 达标方式 | 运营目的 |
| --- | --- | --- | --- |
| 首位有效邀请 | 7 天卡；好友另得 7 天 | 新用户安装 App、登录并主动绑定，7 天内在 2 个自然日使用核心功能，至少收藏一次 | 低门槛双向体验，衡量激活而非点击 |
| App 推荐帖 | 7 天卡 | App 名称、100 字真实使用体验、1 张 App 功能截图、官方下载或邀请入口；公开发布并审核 | 提高 App 认知，带来可归因的下载与使用 |
| App 上手教程 | 30 天卡 | 介绍 App 适合谁、安装方式和核心功能；300 字 + 3 张 App 截图，或 60 秒 App 实操视频；包含下载入口与奖励关系说明 | 累积可长期搜索的上手内容 |
| 3 位好友持续活跃 | 30 天卡 | 每人前 14 天内活跃 3 天，且至少 1 天在第 8–14 天 | 奖励真正留下来的用户 |

每项本期一次，邀请人总上限 74 天；首位好友可以计入 3 人进阶任务。受邀新人每人仅能获一次 7 天奖励，因此每位邀请人带来的奖励成本还需计入新人的份额。避免多级返利、邀请排行榜、强制群发、付费达标及奖励好评。月卡统一定义为 30 × 24 小时。

### 触达与留存

1. **价值发生后再邀请。** 在用户完成收藏整理、成功使用核心功能后，以可关闭的小入口触达；不在首次启动就弹分享。主页「我的」保留长期入口。
2. **按偏好推荐任务。** 愿意轻量分享的用户优先 App 推荐帖，熟悉产品且愿意制作内容的用户优先 App 上手教程；仍可看到全部任务。原型先采用固定顺序，个性化需要真实行为证据与实验。
3. **让受邀人获得即时价值。** 邀请落地页说明邀请关系、双方奖励、完成条件与数据用途。落地页明确产品名称、功能价值和官方下载入口；安装后引导完成推荐帖提到的核心功能，减少新用户迷路。
4. **用内容代替刷屏。** 提供 App 推荐帖提纲、经核准的产品卖点、App 功能截图和官方安装入口，不批量代发、不索取通讯录。分享渠道应适合内容并允许推广。
5. **激活时机交给用户。** 卡片领取后 30 天内可激活，激活时顺延现有同档权益。对于更高档会员，应在服务端明确可用规则后才开放活动，不能以过期逼迫降级。
6. **只提醒关键事件。** 用户同意后通知审核结果、奖励可领、卡片临期；卡片临期建议只提醒一次。PRO 到期前提供真实使用回顾与明确价格入口，避免预勾选续费。

### 推广渠道与素材

- 好友私信：分享 App 用途与邀请入口，按好友安装后的有效体验发奖。
- 社交平台 / 软件社区：用一篇真实 App 推荐帖介绍产品、配功能截图、给出下载路径；按平台允许的推广形式发布。
- 视频 / 图文教程：围绕 App 安装与功能操作回答新用户的问题，让内容持续带来产品搜索与下载。
- 兴趣社群：征得群管理允许后介绍 App，不按转发群数量发奖、不要求上传私人聊天记录；用邀请入口归因有效新用户。

原型已提供可复制的 App 推荐帖提纲。正式素材库建议提供经核准的 App 名称与图标、功能截图、已验证卖点、可编辑文案和带渠道参数的下载链接。不要把点击下载当作安装成功；以 App 首次启动及后续有效使用确认。

### 衡量、预算与试运行

主指标用「每 100 位被触达老用户带来的 D14 留存新用户」，同时查看App 推广 → 落地页打开 → 下载点击 → 首次启动 → 登录绑定 → 有效体验 → 持续活跃的漏斗。事件建议：`plan_view`、`task_open`、`share_intent`、`referral_open`、`download_click`、`app_first_open`、`referral_bound`、`referral_qualified`、`referral_retained`、`content_submitted`、`content_reviewed`、`reward_claimed`、`pass_activated`。`share_intent` 只代表用户触发了分享，不能当作真正发布。

成本观察：已发放与未领取奖励负债、体验期间真实边际服务成本、审核人力、异常比例、自然付费被替代的比例、到期后自愿转化。单位留存获客成本 =（归因的实际体验服务成本 + 审核运营成本）/ 新增 D14 留存用户。不能用卡片标价当作真实成本，也不能仅凭总注册增长证明活动有效。

建议先对具备使用历史的用户小流量试运行，并保留随机对照组；至少等到完整 14 天留存观察窗结束再扩量，进一步观察体验到期后的付费。第一轮只验证双向 7 天邀请是否带来增量留存；第二轮再比较 App 推荐帖与 App 上手教程任务的成本和质量。样本量根据基线与目标效果计算，不预设漂亮的提升数字。

预算由活动级服务端上限控制，同时预留受邀新人奖励成本。预算不足时停止新的参与资格，但已获资格用户在约定期限内达标的奖励必须履约；不能先承诺后拒发。具体活动时间、名额、服务成本与付费影响需上线前根据真实数据确定。

## 后端落地边界

- 服务端保存 `campaign / task_definition / enrollment / referral / submission / reward_ledger / entitlement`，Web 本地状态只用于原型。规则需版本化；奖励、归因、审核、激活均不信任客户端。
- 任务状态：`new → progress / pending → ready → claimed`；内容允许 `pending → rejected → pending`。邀请与持续活跃分别计数；服务端去重事件并防乱序。
- 新用户主动绑定唯一邀请人，绑定后不覆盖；归因窗口从绑定时间开始；可用安装后邀请码补绑处理深链丢失。具体绑定宽限期上线前明确。避免跨设备重复、自邀与批量账号，但共享 IP 只作为复核信号。
- 邀请人与新人的奖励分别入账；唯一键至少包括活动、任务、受益用户、来源事件。发卡与状态更新使用事务 / 幂等写入，领取与激活重试不重复增发。
- 激活在服务端校验卡片归属、状态、有效期、会员档位，并以 `max(now, entitlement_end) + duration` 计算同档顺延，原子消费卡片。金额、权限和会员资格以服务端为准。
- 服务端定义统一自然日时区（建议 Asia/Shanghai），存储 UTC 时间；界面展示用户本地时间。7 / 30 天卡按持续小时计算，活动活跃天数按固定自然日计算。
- 内容只提交必要的公开链接、说明和审核记录，不抓取私域聊天；明确保留期限、删除机制、异常复核和申诉。邀请人只见汇总，不见好友具体收藏与浏览记录。
- 正式 UI 还需接入加载、网络错误重试、资格不符、活动结束、奖励售罄前的资格保护、权益冲突和申诉入口。本原型已演示空列表、审核中、需补充、过期卡与重复领取保护，但没有模拟所有服务端异常。

## 设计与运营依据
